# 宇树 B2 工厂自主巡检项目路线与论文实验方案

## 1. 项目最终目标

机器人在 Jetson 上自主完成多巡检点任务：3D 建图与定位、路线规划、人员和临时障碍物局部避让、到点停车拍照、图像质量评价、不合格时重新选择安全观测位姿、合格后前往下一点。监控电脑只查看地图、图像、状态和日志，不参与机器人决策。

## 2. 系统数据流

```text
LiDAR、IMU、B2 状态、相机
          ↓
时间与外参检查
          ↓
RTAB-Map 3D 建图/定位 ──→ 三维地图与 map→odom
          ↓
二维投影地图 + 实时障碍点云
          ↓
Nav2 全局路径 + 局部代价地图 + 局部避障
          ↓
Python 安全速度桥 ──→ B2 Sport 官方接口
          ↑
巡检任务管理器
          ↓
到达目标 → 完全停车 → 拍照 → 目标区域质量评价
          ↓不合格                         ↓合格
选择下一个已验证候选位姿              保存并前往下一点
```

## 3. 研究范围

成熟模块可以使用 RTAB-Map、Nav2 和宇树官方 Sport 接口。论文创新集中在“面向故障检测输入质量的主动观测位姿选择”。不建议同时宣称提出新的 SLAM、导航、视觉检测和四足控制算法，否则实验量过大且主线不清晰。

推荐论文题目：

> 面向坡地工业场景的图像质量驱动四足机器人主动观测与自主巡检方法

英文方向：

> Quality-aware active viewpoint planning for autonomous quadruped inspection in sloped industrial environments

## 4. 可形成论文贡献的三个层次

### 贡献 1：诊断可用性质量模型

质量分数不能只有拉普拉斯清晰度。建议先使用可解释基线，再用真实数据学习权重：

```text
Q = w1×目标区域清晰度 + w2×目标面积适宜度
  + w3×目标检测置信度 + w4×曝光适宜度
  + w5×下游故障检测可用概率
```

同时设置硬约束：目标必须被检测到、不能过小、不能严重过曝、机器人必须完全停车。
阈值通过独立验证集标定，不应凭经验直接定稿。最终标签最好由合作方故障检测模型
是否正确识别来定义；如果暂时拿不到检测器，先由两名以上标注者判断“刻度/文字/
故障特征是否可辨”，并报告一致性。

### 贡献 2：安全候选观测位姿选择

为每个设备建立多个候选相机位姿，综合评价：

- 预计目标可见度；
- 与目标的距离和夹角；
- Nav2 路径长度；
- 局部代价地图碰撞风险；
- 坡度和地面粗糙度；
- 当前定位置信度。

当前代码先采用“预先验证的候选位姿按顺序尝试”作为可运行基线。取得足够实验数据后，再替换为带代价函数的在线选择算法。

建议在线评分形式：

```text
J(v) = α×预计图像可用概率
     + β×目标可见率
     - γ×到达路径长度
     - δ×局部碰撞风险
     - ε×坡度/落差风险
     - ζ×定位不确定性
```

候选必须先经过 Nav2 可达性和安全距离硬约束，再比较 `J(v)`；不能让高图像分数覆盖
碰撞风险。第一版只做离散候选评分，暂不做连续空间优化，便于复现和消融。

### 贡献 3：面向四足机器人的安全闭环

任务管理器、机器人状态心跳、安全速度桥和超时停车构成闭环。论文可讨论通信中断、定位丢失、相机超时和导航失败时的安全状态转换，但必须通过故障注入实验验证。

## 5. 开发里程碑

| 阶段 | 目标 | 必须保存的证据 | 通过条件 |
|---|---|---|---|
| G0 | 有线基础控制 | 命令响应、视频、方向记录 | 站起/短动/停车/趴下均正确 |
| G1 | 状态与传感器 | rosbag、TF 树、外参记录 | 状态、点云、相机连续且时间合理 |
| G2 | 3D SLAM | 3D 数据库、二维投影图、闭环轨迹 | 地图无明显重影，重复定位误差达标 |
| G3 | 导航避障 | 路径、代价地图、成功/失败日志 | 空场、静态障碍、动态障碍逐项通过 |
| G4 | 主动拍照 | 原图、质量报告、候选位姿日志 | 不合格能调整，合格后自动继续 |
| G5 | 整机自主 | 全流程 rosbag、断网测试 | Jetson 独立运行，电脑退出不影响安全 |

## 6. 户外模拟场景

建议使用约 12 米 × 8 米的平整场地，先不加入坡道。使用胶带或锥桶标出机器人路线和 2 米安全边界。

### 目标 A：距离问题

- 使用打印仪表盘或带细小刻度的设备图片；
- 旁边固定 ArUco 10 号标记；
- 初始观测位姿设置得略远，使目标面积小于阈值；
- 第二个候选位姿靠近，但与目标保持防碰撞距离；
- 预期机器人第一次判定不合格，移动到第二位姿后合格。

### 目标 B：遮挡和视角问题

- 使用带文字、螺栓或接线端子的目标板；
- 旁边固定 ArUco 20 号标记；
- 在正常视线前放置软质泡沫遮挡物；
- 第二、第三候选位姿分别位于目标左前和右前；
- 预期机器人不能盲目前进，应通过 Nav2 到侧向候选位姿重新拍照。

### 坡道场景

坡道必须单独验证。先测量坡度、长度、表面摩擦和两侧保护区域；先人工遥控低速上下坡，再建图，再定位，最后才允许自主导航。不要把新坡道、动态人员和新视觉策略同时放进第一次综合实验。

障碍物使用加重泡沫箱或纸箱，禁止用金属架、玻璃、车辆或真实人员作为第一次避障目标。动态人员实验应先用移动软目标替代。

### 建议的场地尺寸与记录方式

- A、B 目标间距先设为 5～8 米，路线总长控制在 15～30 米；
- 目标板推荐至少 A3 大小，包含 2～3 毫米细线、小字号文字和可重复打印的伪故障；
- 用照度计或手机固定应用记录光照，但正式论文应换用校准设备；
- 用卷尺记录目标距离，用量角器/测距仪记录视角和坡度；
- 相机固定曝光实验与自动曝光实验分开，不要混在同一组统计；
- 遮挡率设置 0%、25%、50%、75% 四档，遮挡物只用软材料；
- 每次移动目标或障碍后拍全景照片并保存场景编号，保证实验可复现。

## 7. 对照实验设计

至少比较以下方法：

1. 固定观测点：到点拍一次，不调整；
2. 只按距离靠近：照片不合格就向前；
3. 本项目方法：质量评价后选择安全候选观测位姿。

每种场景和每种方法前期建议独立重复至少 20 次，并固定相机参数、光照条件范围、
初始位置和障碍物位置。正式论文的次数应由先导实验方差和统计功效分析确定。

## 8. 评价指标

- 最终可用于故障检测的图像比例；
- 目标成功检测率；
- 首次拍照合格率；
- 平均重拍次数；
- 平均位姿调整距离；
- 单个巡检点耗时；
- 整条路线完成率；
- 导航成功率和避障成功率；
- 定位误差与建图重复性；
- 安全停车触发次数；
- Jetson CPU、GPU、内存和功耗。

“图像可用于故障检测”应由独立标注或下游检测器性能定义，例如故障检测准确率达到预设下限，而不只是主观认为照片清楚。

## 9. 数据集和实验记录

每次实验保存：

- 原始相机图像和目标框；
- 图像质量各分项及最终结果；
- 机器人和候选位姿；
- Nav2 路径、局部代价地图和速度；
- LiDAR、里程计、TF 和机器人状态；
- 场景编号、光照、坡度、遮挡率和障碍布局；
- 软件版本、参数文件和 Git 提交编号；
- 成功、失败和人工接管原因。

## 10. 一个月内建议安排

### 第 1 周

精读文献清单中的 1～7；完成 G0、G1；取得真实话题、消息频率、TF、外参和第一份
rosbag；根据实测结果修正驱动。文献笔记见
[本周文献阅读清单](文献阅读/本周文献阅读清单.md)。

### 第 2 周

完成平地和坡道 3D 建图；形成可重复地图；测量定位误差；生成对应二维 Nav2 地图。

### 第 3 周

完成空场导航、静态障碍和移动软目标避障；标定 footprint、速度、加速度、膨胀半径和停车距离。

### 第 4 周

搭建 A/B 目标，完成 ArUco 目标定位、图像质量阈值、候选位姿闭环和对照实验；整理失败案例，为进厂测试准备检查表。

## 11. 无线与部署原则

无线板卡型号不能只按“Ubuntu 22.04 免驱”选择，还要匹配 Jetson 型号、可用 M.2 Key、USB 或 PCIe 接口、内核版本、天线和供电。部署后所有自主节点随 Jetson 启动；电脑只订阅监控数据。网络断开时 Jetson 必须继续安全运行或停车，不能依赖电脑发送停车指令。

2026-09-09 正反面照片已确认板卡为创乐博 Jetson Orin Nano Super CLB
Developer Kit，背面 J10 已安装 RTL8822CE，Main/Aux 双天线已连接，并有
HP FX700 256GB NVMe。当前不再购买无线板卡，先验证 JetPack 驱动、5GHz
丢包、吞吐和安装到 B2 后的覆盖。若金属遮挡导致信号差，先把双天线移到
外壳外；AX210 只作为实测证明确有必要后的升级，不作为当前采购项。

最终网络采用 B2 有线直连 Jetson、Jetson Wi-Fi 接入监控局域网。最终供电拟从
B2 经官方确认的受保护附件输出，经过保险和工业级 DC-DC 转为 Jetson 需要的
19V；在 B2 接口针脚、允许电流和上电时序确认前，不进行板载取电试接。

## 12. 当前代码完成度说明

代码已经具备 Python 安全速度桥、Python 状态转换、RTAB-Map 六自由度建图/定位启动、
Nav2 低速局部避障基线、严格路线解析、候选观测位姿任务管理、ArUco 扩展目标区域、
目标区域图像质量评价、照片/JSON 记录、状态—雷达—定位三重安全许可和
Jetson 安全条件就绪后的可选自动启动。7 个包已在本机完成构建。最新测试数据
和受限环境中的 XML schema 检查说明见 [代码检查报告](代码检查报告.md)。

仍需真实 B2、LiDAR 和相机数据完成固件接口、外参、传感器时钟、导航参数和质量阈值
标定；`ros-humble-pointcloud-to-laserscan` 已于 2026-09-08 安装并能被 ROS2 找到。当前 Nav2 依赖二维
投影障碍信息，不等同于四足地形可通行性规划；坡地论文版本还应加入高程/坡度风险层。
未经这些实测，工程只能称为“软件基线完成并通过离线检查”，不能称为完整实机验收。

## 13. 投稿前必须补齐的实验

1. **定位与地图**：至少三次重复建图，报告闭环前后轨迹、回到起点误差、坡面高度
   误差和 Jetson 资源占用；
2. **局部避障**：静态箱体、移动软假人、窄通道分别统计成功率、最小障碍距离、耗时
   和人工接管；
3. **主动拍照**：固定点、只靠近、顺序候选和质量感知评分四组对照；
4. **质量模型消融**：依次去掉清晰度、曝光、目标面积、检测置信度和下游任务项；
5. **坡度泛化**：至少三个坡度档位，并报告上坡、坡顶和下坡，不只展示成功视频；
6. **故障注入**：相机断流、雷达断流、定位 TF 停更、任务节点退出和监控电脑断网；
7. **跨场景迁移**：户外模拟场景标定后，在工厂只做少量阈值调整，报告性能下降与
   调整量。

论文主贡献应放在“诊断可用图像驱动的安全观测位姿选择”。RTAB-Map、Nav2 和宇树
Sport 接口属于系统组件，除非做了有充分对照的新方法，否则不要把集成描述成算法创新。
