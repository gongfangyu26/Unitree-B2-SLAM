# 宇树 B2 有线基础控制调试手册

> 2026-09-08 已按本手册完成实机验证。可靠前进参数为 `0.30 m/s`、`0.60 s`，
> 后续 SLAM 开发不要重复本测试；本文件仅用于硬件或控制链发生变化后的复验。

## 1. 本次调试只验证什么

本次只验证电脑或 Jetson 能否通过宇树官方 ROS2 Sport 接口完成：

1. 站起；
2. 平衡站立；
3. 低速、短时间前进和转向；
4. 主动停车和超时自动停车；
5. 趴下或蹲下；
6. 接收 `/api/sport/response` 响应。

本次不要启动 SLAM、Nav2、巡检任务、旧键盘节点或速度桥。测试程序会直接向 B2
官方接口发出有限时长指令。

测试程序的源代码位于：

```text
src/b2_twist_bridge_py/b2_twist_bridge_py/safe_motion_test.py
```

接口编号依据宇树官方 B2 专用头文件：
[`ros2_b2_sport_client.h`](https://github.com/unitreerobotics/unitree_ros2/blob/master/example/src/include/common/ros2_b2_sport_client.h)。

## 2. 场地与人员要求

- 使用平整、干燥且不打滑的地面，空旷范围至少 3 米 × 3 米。
- 机器人周围 2 米内不得站人，不得有网线、电源线或硬质障碍物。
- 一人操作终端，另一人观察机器人并手持遥控器或急停装置。
- 电量过低、机器人带负载、地面有坡度或机械结构异常时不得测试。
- 任何动作异常时，先按键盘 `x`；若无效，立即使用物理急停或遥控器。

## 3. 确认有线网络

在连接网线的电脑上执行：

```bash
ip -br address
```

作用：列出网卡名称、启用状态和 IP 地址。记录有线网卡名称，例如 `enp3s0`。

```bash
ip route
```

作用：查看电脑到机器人网段的路由。不要在不知道机器人 IP 时随意修改网卡地址。

从宇树 App、机器人标签或现场网络配置中取得真实机器人 IP，然后执行：

```bash
ping -c 3 <机器人IP>
```

预期：收到 3 个响应。若完全不通，先检查网线、网卡地址和机器人 IP，不要继续发控制指令。

## 4. 加载 ROS2 和宇树 SDK

打开终端 1：

```bash
source /opt/ros/humble/setup.bash
```

作用：加载 Ubuntu 22.04 对应的 ROS2 Humble。

继续加载包含 `unitree_api` 和 `unitree_go` 的宇树消息工作空间。本机已经确认可用的
路径如下：

```bash
source /home/gongfangyu/unitree_ros2/cyclonedds_ws/install/setup.bash
```

作用：让 ROS2 找到宇树消息定义和通信组件。

指定 CycloneDDS。先把示例网卡 `enp3s0` 换成第 3 节实际查到的有线网卡名：

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export B2_NET_IF=enp3s0
export CYCLONEDDS_URI="<CycloneDDS><Domain><General><Interfaces><NetworkInterface name=\"${B2_NET_IF}\" priority=\"default\" multicast=\"default\" /></Interfaces></General></Domain></CycloneDDS>"
```

作用：强制 ROS2 使用宇树通信所需的 CycloneDDS，并只在连接 B2 的有线网卡上通信。
本机的 `~/unitree_ros2/setup.sh` 仍写着 ROS2 Foxy 和固定网卡名，Ubuntu 22.04/Humble
调试时不要直接加载那个旧脚本。

```bash
ros2 pkg prefix unitree_api
ros2 pkg prefix unitree_go
```

预期：两条命令都输出安装路径。若提示找不到包，说明宇树工作空间没有正确编译或没有被加载。

设置与机器人一致的 DDS 域。若现场没有修改过，一般从 0 开始验证：

```bash
export ROS_DOMAIN_ID=0
```

确认环境：

```bash
echo "$RMW_IMPLEMENTATION"
echo "$B2_NET_IF"
ros2 pkg prefix unitree_api
ros2 pkg prefix unitree_go
```

预期：第一条输出 `rmw_cyclonedds_cpp`，后两条包查询都输出安装路径。每打开一个新
终端，都要重新执行本节的 `source` 和 `export` 命令。

## 6. 检查官方控制话题

```bash
ros2 topic list | sort
```

确认至少存在：

```text
/api/sport/request
/api/sport/response
```

继续检查类型：

```bash
ros2 topic type /api/sport/request
ros2 topic type /api/sport/response
```

预期分别包含 `unitree_api/msg/Request` 和 `unitree_api/msg/Response`。

```bash
ros2 topic info /api/sport/request -v
```

作用：查看发布者、订阅者和 QoS。必须能够看到机器人侧订阅者。若订阅数为 0，停止调试并检查 DDS 网络。

## 7. 排除多个控制源

```bash
ros2 node list
ros2 topic info /api/sport/request -v
```

关闭旧键盘节点、Nav2、巡检节点和其他发布 `/api/sport/request` 的程序。首次测试只能保留一个控制程序。

## 8. 启动安全测试

```bash
ros2 run b2_twist_bridge_py safe_motion_test --ros-args -p linear_speed:=0.30 -p lateral_speed:=0.08 -p angular_speed:=0.20 -p motion_pulse_sec:=0.60
```

参数含义：

- `linear_speed:=0.30`：B2 实测能够可靠形成前向位移的速度；
- `lateral_speed:=0.08`：左右平移速度限制为 0.08 米每秒；
- `angular_speed:=0.20`：转向速度限制为 0.20 弧度每秒；
- `motion_pulse_sec:=0.60`：已验证短运动持续 0.60 秒，随后自动发送 `StopMove`。

严格按以下顺序操作，每一步完成后都等待机器人稳定：

1. 启动后先按 `u` 验证锁：机器人必须不动作，终端提示“请先按 i 解锁”。
2. 按 `i` 一次：测试进入解锁状态；只有现场人员确认安全后才能执行。
3. 按 `u` 一次：发送 `StandUp`，观察机器人是否正常站起。
4. 按 `b` 一次：发送 `BalanceStand`，确认机器人稳定。
5. 按 `w` 一次：机器人只应向前移动几厘米，然后自动停止。
6. 按 `x` 一次：再次明确发送 `StopMove`。
7. 按 `q` 一次：机器人应小角度左转，然后自动停止。
8. 按 `x` 一次：明确停车。
9. 确认机器人完全静止后按 `j` 一次：发送 `StandDown`。
10. 按 `i` 一次：重新锁定，程序会再次发送停车指令。
11. 按 `Ctrl-C`：程序发送停车指令并退出，不额外改变姿态。

第一次不要测试后退、侧移或加速。前进和左转方向验证正确后，再逐项测试其他方向。
若按键方向与实际相反，立即按 `x` 并记录“按键、期望方向、实际方向”，不要现场随意
修改正负号后继续扩大速度。

## 9. 通过标准

以下条件全部满足才算基础控制通过：

- 站起、平衡站立和趴下动作与按键一致；
- 前进和转向方向正确；
- 每次运动约 0.60 秒后停止，不出现持续运动；
- 终端能够收到对应 `api_id` 的机器人响应；
- 退出程序后机器人不再运动；
- 没有第二个节点同时发布控制请求。
- 锁定状态下除停车外的动作全部被拒绝。

本次通过只代表 Sport 控制链路可用，不代表里程计、SLAM、导航和避障已经通过。

```bash
ros2 topic list > ~/b2_topic_list.txt

ros2 topic info /api/sport/request -v > ~/b2_sport_request_info.txt
```

## 11. 常见故障处理

### 能 ping 通但看不到宇树话题

依次检查：`B2_NET_IF` 是否为有线网卡、`RMW_IMPLEMENTATION` 是否为
`rmw_cyclonedds_cpp`、所有终端的 `ROS_DOMAIN_ID` 是否一致。然后执行：

```bash
ros2 daemon stop
ros2 daemon start
ros2 topic list
```

作用：清除可能使用旧 DDS 环境启动的 ROS2 后台发现进程，再重新发现话题。

### 话题存在但机器人不动作

先确认 `/api/sport/request` 有机器人侧订阅者，并确认程序中已经按 `i` 解锁。不要通过
提高速度来排查通信问题。保存以下输出：

```bash
ros2 topic info /api/sport/request -v
ros2 topic echo /api/sport/response
```

### 机器人没有按时停车

立即使用物理急停或遥控器接管，之后关闭测试程序。不要在同一场地继续试验。检查是否
有其他节点发布 `/api/sport/request`，并把 rosbag、终端日志和现场视频一起保存。
