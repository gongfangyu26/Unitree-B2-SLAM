# 宇树 B2 工厂巡检工程代码检查报告

> 历史报告说明：本文早于 2026-09-09 实机调试。后退、左右横移、Jetson Wi-Fi 和
> 静止 3D SLAM 的最新结论以 `docs/2026-09-09_B2_Jetson_实机调试记录.md` 为准。

## 1. 检查结论

当前工程已形成以 Python 为主的可编译、可分阶段调试基线，包含：

- B2 Sport 基础动作与速度控制；
- 状态、里程计、TF 和关节状态转换；
- RTAB-Map 六自由度三维建图/定位基线；
- Nav2 全局路径与基于实时点云投影的局部避障；
- 多巡检点任务、拍照、质量判断和候选观测位姿切换；
- 机器人状态、雷达和定位三重许可，以及心跳、超时停车和默认锁定；
- 路线标定完成后，可选择由 Jetson 在安全条件齐备时自动开始巡检。

这些结论仅表示“软件基线通过离线检查”。由于本次没有连接真实 B2、
RoboSense 雷达和相机，不能宣称整机功能已经实机验收。

补充实机基线：`docs/B2_DEBUG_LOG_2026-09-08.md` 已确认网络、CycloneDDS、Sport
控制、0.30 m/s 前进、0.20 rad/s 左转和自动停车。后续不重复这些测试，尚未验收的
重点转为点云/里程计坐标系、3D SLAM、Nav2 和拍照闭环。

## 2. B2 官方接口核对

接口依据为宇树官方 `unitree_ros2` 仓库中的 B2 专用头文件
[`ros2_b2_sport_client.h`](https://github.com/unitreerobotics/unitree_ros2/blob/master/example/src/include/common/ros2_b2_sport_client.h)，
并已与当前电脑的本地宇树源码逐项比较。

主流程实际使用的接口如下：

| 功能 | B2 API 编号 | 参数 |
|---|---:|---|
| 平衡站立 | 1002 | 无 |
| 停止运动 | 1003 | 无 |
| 站起 | 1004 | 无 |
| 趴下/降低机身 | 1005 | 无 |
| 恢复站立 | 1006 | 无 |
| 速度控制 | 1008 | JSON：`x`、`y`、`z` |

控制和响应话题分别为 `/api/sport/request` 和 `/api/sport/response`，消息为
`unitree_api/msg/Request` 和 `unitree_api/msg/Response`。

本轮发现原编号表的高级动作部分沿用了 A2 定义。现已替换为 B2
专用编号并增加自动测试。项目仍只允许基础白名单动作，倒立等危险动作
即使有官方编号也会被拒绝。

## 3. 本轮确认并修复的问题

### 3.1 基础控制

- 默认上锁，`start_enabled` 不能在启动瞬间绕过安全锁；
- 解锁前重复发送 `StopMove`，避免继承其他控制源的旧速度；
- 对前后、侧向和转向分别限速，拒绝 NaN 和无穷大；
- 0.35 秒无新速度时停车，心跳、机器人状态或自主感知链超时时自动锁定；
- 实机测试程序默认锁定，当前默认使用已验证的 0.60 秒短脉冲，
  后退和横移首测可显式改为 0.30 秒；
- 测试速度和脉冲时间有硬上限，超出范围时节点拒绝启动。

### 3.2 状态、里程计与 TF

- `publish_tf` 按布尔值解析，话题和坐标系名称统一；
- 检查错误码、数组长度、非有限数值和四元数长度，并对四元数归一化；
- `/odom` 和 `odom→base_link` 使用完全相同的接收时刻；
- 给里程计加入可配置的保守协方差，不再用全零表示“完全确定”；
- `/b2/state_ok` 持续发布状态新鲜度，非法数据立即使其变为 `false`。

### 3.3 3D SLAM 与导航

- 新建 RTAB-Map 三维建图/定位包，保留六自由度，不强制平面化坡道位姿；
- 修复总启动文件与下层 launch 公开参数不一致的问题，不再向下层 launch
  传入未声明的 `odom_backdate_sec`；
- 增加显式三维数据库路径，新建地图时才删除指定数据库；
- 点云只在兼容节点中以主机接收时间重写，里程计与对应 TF 保留相同时间戳；
- 修正 RTAB-Map 命名空间下二维占据地图的保存话题为 `/rtabmap/map`；
- Nav2 采用低速、扩大轮廓和局部体素障碍层的保守初值；
- 安全监视器同时检查二维雷达接收时间、消息时间戳、量程数值和 `map→base_link`
  定位变换的新鲜度。
- 点云、里程计和雷达 frame 均改为 launch 参数，默认值来自实机 topic 清单；
- 增加 `/b2_slam/preflight_ok` 和 JSON 报告，检查点数、字段、频率、时间戳、
  `odom→base_link` 语义和雷达外参；巡检安全许可必须同时通过该检查。
- 根据实测起步特性把自主前进上限和最低有效值设为 0.30 m/s；后退和横移在
  完成独立实机验收前默认禁止。
- 横移上限和最低有效速度已从总启动文件透传到 Python 速度桥，
  但只有实机验收后才能修改并打开 `allow_lateral`。

### 3.4 巡检任务与图像质量

- 路线和目标 YAML 均经过严格类型、有限数值、重复名称和数量上限检查；
- 任务管理器使用 Nav2 `NavigateToPose`，不再使用“激光左右分区后直接扭转”的旧方法；
- 拍照前等待机器人稳定，并且只接受拍照请求之后到达的新图像和同批目标框；
- 质量判断包含目标存在性、置信度、目标面积、目标区域清晰度、亮度、暗部和过曝；
- 每张原图保存同名 JSON 报告，便于论文实验追溯；
- ArUco 在户外验证时只用于定位目标，评价区域可扩展到标记周围的设备板；
- 导航、图像或安全状态失败时取消目标、停止拍照、关闭控制锁；
- 增加默认关闭的 `mission_autostart`。打开后仍需经过启动延时、安全许可和
  Nav2 就绪检查，使监控电脑可以不发送任何任务指令。

### 3.5 工程结构

- 首次运动测试程序已放在
  `src/b2_twist_bridge_py/b2_twist_bridge_py/safe_motion_test.py`；
- 旧 C++ 驱动、旧 C++ 速度桥和旧 Go2 键盘节点均通过 `COLCON_IGNORE`
  排除在默认构建之外；
- 旧固定路线节点的已安装执行入口已移除，源码仅保留作对照；
- 新编写的功能代码和调试文档使用中文注释与说明。第三方源码、法律声明和 ROS
  自动生成的许可证模板保留原文，不应翻译或删改。

`colcon test` 中 `b2_description` 的 `xmllint` 试图从
`http://download.ros.org/schema/package_format3.xsd` 下载官方 schema，但本次受限运行环境
拒绝了网络访问，因此它报告 1 个外部 schema 加载失败（结果汇总会把同一失败
计数两次）。该包的 flake8、CMake lint 和 PEP257 均通过，10 个 `package.xml`
也已用本地 XML 解析器全部通过。这个结果应记为“外部校验资源不可达”，不是
`package.xml` 语法错误。

## 6. 必须现场核对的数据

- 机器人 IP、有线网卡名、CycloneDDS 配置和 `ROS_DOMAIN_ID`；
- B2 固件实际发布的 `/lf/sportmodestate`、`/lf/lowstate` 和错误码；
- `/rslidar_points` 的类型、频率、`frame_id` 和时间戳；
- 相机话题、编码、分辨率、帧率、曝光和时间戳；
- B2 `x/y/z` 速度正方向和停车响应；
- LiDAR/相机到 `base_link` 的六自由度外参；
- 平地、坡道、湿滑面的制动距离和动态摆腿空间；
- RTAB-Map 重复路线漂移、闭环后误差和 Jetson 资源占用；
- 图像质量阈值、目标区域和所有候选位姿的真实安全性。

## 7. 不应启动的旧入口

- `b2_teleop_ctrl_keyboard`：旧 Go2 来源键盘程序，接口编号和停止逻辑不适合 B2；
- `b2_driver` 和 `b2_twist_bridge`：旧 C++ 对照代码；
- `fixed_route_3d_patrol_node.py` 及其 launch：旧的直接速度巡检基线，没有当前安全闭环。

当前入口：

```bash
ros2 run b2_twist_bridge_py safe_motion_test
ros2 launch b2_driver_py driver.launch.py use_rviz:=false
ros2 launch b2_factory_inspection mapping_3d.launch.py
ros2 launch b2_factory_inspection autonomous_inspection.launch.py --show-args
```

真机操作顺序以《有线基础控制调试手册》和《完整巡检系统分阶段调试手册》为准。
