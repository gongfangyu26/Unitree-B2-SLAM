## 四、Nav2 点云和局部代价地图修复

### 4.1 修正后点云中断

故障现象：

- `/rslidar_points` 仍有约 9.7 Hz；
- `/b2_navigation/cloud_fixed` 无数据；
- `/scan` 无数据；
- 话题 endpoint 和节点仍存在；
- 安全监视器报告二维雷达超时和过去时间外推。

证据显示 RoboSense 原始发布端为 `RELIABLE`，时间戳修正节点当时为
`BEST_EFFORT`。本日修改：

- `pointcloud_timestamp_fix.py` 增加 `input_reliability` 参数；
- 导航启动时显式设置 `input_reliability=reliable`。

**实机已验证：**

- `/b2_navigation/cloud_fixed` 恢复到约 9.5 Hz；
- `/scan` 恢复到约 9.6～10 Hz；
- 运行参数 `input_reliability` 为 `reliable`。

### 4.2 局部代价地图

原始告警：传感器原点高度约 `1.27 m`，超出 VoxelLayer 高度
`0.00～0.78 m`，无法 raytrace。

本日把局部代价地图从 `VoxelLayer` 改为适合当前 `/scan` 二维输入的
`ObstacleLayer`。

**实机已验证：**

```text
/local_costmap/local_costmap plugins =
['obstacle_layer', 'inflation_layer']
```

重启后在本次静止观察期内未再看到旧 VoxelLayer 高度越界告警。

## 五、AMCL 初始位姿问题

### 5.1 公共 `/initialpose` 冲突

实机 ROS2 graph 显示：

- B2 厂商 `/QtServer` 在公共 `/initialpose` 上发布；
- AMCL 原先也订阅公共 `/initialpose`；
- AMCL 反复保持在 `(0,0,0)`。

本日在 `navigation.launch.py` 中为 AMCL 增加独立话题参数，默认：

```text
/b2_navigation/initialpose
```

**实机已验证：**

- AMCL 只订阅 `/b2_navigation/initialpose`；
- `/QtServer` 继续只在公共 `/initialpose` 发布；
- 公共 `/initialpose` 对 AMCL 的直接话题冲突已隔离。

### 5.2 零位姿自动初始化

隔离话题后 AMCL 仍保持原点。运行参数证据：

```text
set_initial_pose = True
initial_pose.x/y/yaw = 0.0/0.0/0.0
```

因此把 `set_initial_pose` 修改为 `false`，禁止 AMCL 启动时伪造地图原点位姿。

**实机已验证：**

- Jetson 上同步、编译并重启后 `set_initial_pose=False`；
- 发布初始位姿前，`/amcl_pose` 不再发布错误的 `(0,0,0)`；
- 发布初始位姿前，`map -> base_link` 不存在；
- `/b2/autonomy_reason` 正确变为“缺少 map 到 base_link 的定位变换”；
- 两级控制锁均为 `false`。

### 5.3 尚未解决

向 `/b2_navigation/initialpose` 连续发布已知位姿，并调用
`/request_nomotion_update` 后：

- `/amcl_pose` 仍无输出；
- `map -> base_link` 仍不存在；
- 安全监视器拒绝导航；
- 两级锁仍为 `false`。

**当前推测，需要下一次实验确认：**

- 需确认 AMCL 的 topic callback 是否收到消息以及终端日志中是否出现
  `initialPoseReceived` / `Setting pose`；
- ROS2 Humble 安装的 AMCL 提供 `/set_initial_pose`
  `nav2_msgs/srv/SetInitialPose` 服务，可以直接调用同一初始位姿处理函数；
- 本日尚未来得及执行服务调用，机器人电量耗尽后中止。

重要安全结论：曾出现 `map -> base_link` 为原点时
`/b2/autonomy_reason` 仍报“自主导航条件已满足”。这说明现有安全监视器
仅检查 TF 存在性/时效性，不能证明位姿真实。后续必须增加
AMCL 已初始化和位姿合理性检查；在此前不得只凭 `autonomy_ok=true`
解锁。
