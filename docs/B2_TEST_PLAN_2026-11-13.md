ros2 node list

## 4. G2：二维导航地图与静止定位

先对照 PGM 底图、PCD、静态层、实时障碍层和现场墙体。隐藏代价图只改变显示，
不能消除底图黑点；清空内存代价图也不会修改 PGM。
需要重生成二维图时使用原库副本，保留原件和参数；三维保高点云不直接充当
已经验收的二维导航图。地图来源无法确认或墙体不对齐时，不进入自主运动。

准备好本次导航图后，在每个相关终端设置真实路径；以下两项由现场填写，
不是旧场地示例坐标或固定文件名：

```bash
read -r -p '本次已核对的二维地图 YAML 绝对路径: ' B2_MAP_YAML
read -r -p '本次短测路线 YAML 绝对路径（使用新编号）: ' B2_ROUTE_YAML
test -f "$B2_MAP_YAML"
test ! -e "$B2_ROUTE_YAML"
```

检查失败即停止，换新实验编号；录点保存会替换目标路线文件，不覆盖已有实验路线。

驱动已在 G1 唯一运行时启动待命流程，明确覆盖入口的 0.60/600 默认值：

```bash
ros2 launch b2_factory_inspection corridor_patrol.launch.py \
  map:="$B2_MAP_YAML" waypoints_file:="$B2_ROUTE_YAML" \
  start_driver:=false use_rviz:=false \
  route_mode:=once laps:=1 max_linear_x:=0.30 \
  goal_timeout_sec:=25.0 mission_timeout_sec:=60.0 \
  code_revision:="$(git rev-parse HEAD)"
```

上面的版本标记仅适用于 G0 确认源码干净的已提交版本；若有改动，必须另存 diff
及新增文件快照，标明 dirty，不能仅凭 HEAD 声称可复现。
不存在驱动时先返回 G1；不重复启动。AMCL 是本阶段唯一 `map -> odom` 来源，
旧 RTAB-Map 建图/定位应正常退出并保存数据库。

在已打通 DDS 的 PC 上查看完整诊断视图：

```bash
ros2 run rviz2 rviz2 \
  -d "$(ros2 pkg prefix --share b2_navigation)/rviz/navigation.rviz" \
  --ros-args -r /initialpose:=/b2_navigation/initialpose
```

用 `2D Pose Estimate` 填入现场实际位置和方向，观察激光与地图墙体对齐。
检查 `/amcl_pose`、`map -> base_link`、`/b2/autonomy_reason` 和两级锁；
不能将 RViz 全局状态 Ok 单独当作定位验收。

```bash
ros2 topic echo /amcl_pose --once
timeout -s INT 5s ros2 run tf2_ros tf2_echo map base_link
ros2 topic echo /b2/autonomy_reason --once
ros2 topic echo /b2_navigation/armed --once
ros2 topic echo /b2/control/enabled --once
ros2 param get /b2_safe_twist_bridge max_linear_x
ros2 param get /controller_server FollowPath.max_vel_x
ros2 param get /controller_server FollowPath.max_speed_xy
```

通过标准：两锁 false；三项速度上限均为 0.30；实际定位/朝向合理、激光对齐，
安全检查无阻断；二维图中的可通行区域已与现场核对。

## 5. G3：只录点、只规划

清楚确认当前路线后，用 RViz `Publish Point` 在前方净空处只选一个短测点，
目标距离不超过 0.5 m。查看接受/拒绝原因；禁止降低录点代价阈值或缩小机体
来强行放行。新路线使用 `inspect=false`，每点仅一个位姿。

```bash
ros2 service call /b2_navigation/waypoints/save std_srvs/srv/Trigger "{}"
```

当前录点器对单点路线写入 `yaw_deg: 0.0`。保存后打开该 YAML，将唯一目标的
`yaw_deg` 改为现场已核对的当前 map 航向（角度），检查目标在机器人前方，
避免首次短测附带转向到地图零度；该值不能凭机器人坐标变量名猜测。
完成后保持双锁关闭，再检查规划：

```bash
ros2 service call /patrol/validate std_srvs/srv/Trigger "{}"
timeout -s INT 5s ros2 topic echo /patrol/state
```

状态话题可能只在变化时发布，同时查看巡逻节点终端的 READY 和服务响应，
不能仅因订阅开始后没收到旧状态就判定规划成功或失败。

通过标准：保存成功、两锁 false、逐段规划 READY，路径在现场净空范围内；
规划不会发送导航目标。检查在 60 s 内有效，路线、位姿或安全条件改变后重新 validate。
G3 失败就停留地图/定位诊断，当天也可仅完成这些检查并保存失败证据。

## 6. G4：人工解锁、单目标与停车

仅在 G0–G3 全部通过、操作者清场并再次确认可靠人工停车手段后执行。
单次目标 ≤0.5 m、上限 0.30 m/s，限制 25/60 s；观察实际位移、偏航与停车。

```bash
ros2 service call /b2/navigation/set_armed std_srvs/srv/SetBool "{data: true}"
ros2 service call /b2/control/set_enabled std_srvs/srv/SetBool "{data: true}"
ros2 service call /patrol/start std_srvs/srv/Trigger "{}"
```

异常时立即人工停车；在通信仍可用时关闭底层锁、导航门并停止任务：

```bash
ros2 service call /b2/control/set_enabled std_srvs/srv/SetBool "{data: false}"
ros2 service call /b2/navigation/set_armed std_srvs/srv/SetBool "{data: false}"
ros2 service call /patrol/stop std_srvs/srv/Trigger "{}"
```

服务成功或软件 STOPPED 均需配合现场确认物理停稳。每次成功/失败都记录，
初次通过后按相同条件至少重复 3 次；到点误差、偏航、停车距离/时间和中止原因
逐项记录，不在机器人运动时为测试超时主动切断 SSH 或网络。
通过后才另设小转向、小闭环实验；不在同一实验中同时升速、改图和改控制参数。
